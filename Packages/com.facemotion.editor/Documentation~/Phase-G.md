# Phase G: Direct VRChat Integration

Phase G plans first, validates without mutation, and applies only after the explicit **Apply Direct Integration** action. It targets the SDK 3.10.5 `VRCAvatarDescriptor` FX layer, expression parameters, and expression menu.

The backend creates a copy of the FX controller, parameters asset, and root menu under the selected `Assets/` folder. It adds a Bool parameter, a Write-Defaults-off `Off`/`On` FX layer and transitions, and a root FaceMotion submenu containing a Toggle. Existing user assets are never edited.

Planning blocks missing descriptor, clip, or output folder; unsafe or unmanaged generated output folders; parameter and animator parameter conflicts; parameter budget overflow; root menu capacity; missing custom FX controller; FaceMotion layer collisions; Write Defaults states; and competing animated bindings. The plan is read-only and shows the proposed parameter, FX-layer, and asset names in the window. A manifest records original descriptor references and every owned asset. Applying again first rolls back the manifest for that avatar. Rollback restores the original descriptor references, then deletes only assets listed in `OwnedAssetPaths` that sit inside the manifest folder and use a known FaceMotion-generated filename; tampered paths are reported and skipped. After owned assets and the manifest are deleted, the generated root folder is deleted only when it is FaceMotion-owned and completely empty. If it still contains foreign content, the folder is retained and a `FM-OWNERSHIP-FOREIGN-CONTENT` diagnostic is reported so a user memo or unrelated subfolder survives. Reapply reuses the same generated folder when possible and never deletes a foreign sibling. If applying fails before descriptor assignment, only assets created by this attempt are removed and the descriptor remains unchanged. No folder, file, or prefix ever justifies deletion by itself.

Phase G does not include Modular Avatar, contacts, physbones, avatar optimization, upload automation, or any Phase H system.
